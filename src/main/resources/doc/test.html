Identifies test case name. Each test case must have a name as a simple String, for example:

- test: Simple test without parameters

The name can also have parameters, for example:

- test: Simple test with <param1> and <param2>

where param1 and param2 are assigned from Cucumber feature file or from java-based step definition (ex. when executing 'BaseStepDefs.runTestCaseProcessing' method)

How to run

  • 1) From Cucumber feature file. In a step, you should set the exact name as defined in '- test', and it's important to add at the end:
    • . - if there are no parameters to provide
    • : - if there is Map-like parameters to provide
    • > - if there is DataTable parameters to provide
    for example (note the special chars at the end of each steps):

    (feature file:)

    Given something is up and running.
    When run some request:
    | param1 | some value |
    Then verify the response with flag <success> returned>
    | param1 | param2 | success |
    | value1 | value2 | true |

    (YAML file:)

    - test: something is up and running
    # some test case properties go here...

    - test: run some request

    # some test case properties go here...
    request:
    a: <param1>

    - test: verify the response with flag <success> returned
    # some test case properties go here...
    request:
    a: <param1>
    b: <param2>

    These special characters at the end of test step are intended for the framework to differentiate between the step defs defined in YAML and in Java.

  • 2) From Java-step definitions. It must extend 'BaseStepDefs' class from Chronos and use the following methods to run the yaml-based test cases:
    • runTestCaseProcessing(String testCaseName)
    • runTestCaseProcessing(String testCaseName, Map<String, String> parameters
