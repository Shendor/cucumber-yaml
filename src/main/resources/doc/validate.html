Validation details for a result of the test case execution (optional).
For this property you need to describe the validation rules for the result of test case execution
This is done by assigning validate(<field or property extractor function>) of the actual value from the execution result and the expected value (please see the list of supported extractor functions and comparators below).
The framework identifies a type of the validation based on the first parameters inside validate() and applies an appropriate validator to the whole list of validations.
NOTE: You should check documentation and examples for a specific test case type (ex. HTTP, DB, MQ, etc.) to know what response does it return and how to validate it.

Supported property extraction functions:

  • field name - extracts a value from this field name, if the result of test execution is Map<String,String>, ex
    # if result is a Map, then the value is extracted from key 'field1' and compared with text 'expected value'
    validate(field1): expected value     # if result is a List of Map, then the value is extracted by key from each item of list and checked that at least one item complies with the validation rules
    - validate(field2): expected value 1
    validate(field3): expected value 2
  • json_path(path.to.field) - extracts value from a json result, ex:
    # if result is a Json String, then the value is extracted from path 'a.b.c' and compared with text 'expected value'
    validate(json_path(a.b.c)): expected value
  • xpath(/path/to/field) - extracts value from a xml result by xpath, ex:
    # if result is a XML String, then the value is extracted from path 'a/b/c' and compared with text 'expected value'
    validate(xpath(a/b/c)): expected value
  • response() - extracts the whole result and convert it to String, ex:
    validate(response()): expected value
  • SPeL expressions - validates result using Spring Expression Language, ex:
    # if result is a Java-POJO object with property int statusCode, then this expression checks if it equals to 200
    validate: "#that(statusCode, 200)"     # if result is a Java-POJO object with property String body as Json, then this expression extracts value by json path and checks that it equals to 'expected value'
    validate: "#that(#jsonPath(body, 'a.b.c'), expected value)"

Supported comparators:

  • equals - default comparator, ex:
    validate(field1): some text
  • contains(some text) - this comparator checks if String value contains the expected text, ex:
    # the value of the field 'field2' will be converted to String and check if it contains 'some text'
    validate(field2): contains(some text)
  • hasSize(number) - retrieves a size of the actual value and compare it with the expected size, ex:
    # assuming that the value of the field 'field3' is a List or Map, then it checks whether its size is 1
    validate(field3): hasSize(1)
  • regex(pattern) - matches the value with the provided regex pattern, ex:
    # the value of the field 'field4' will be converted to String and check if it matches the regex 'field_a='[\w\s]+'.*'
    validate(field4): regex(field_a='[\w\s]+'.*)
  • not(comparator function) - negates the verification result of the comparator. You can use any of available comparators inside 'not()', ex:
    validate(field5): not(contains(something))
  • OR operator - combines comparators with OR, meaning that at least 1 should pass, ex:
    validate(field6): ACCEPT OR AVAILABLE OR NONE
